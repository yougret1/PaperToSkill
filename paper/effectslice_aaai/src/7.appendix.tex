\section{Protocol Pseudocode}
\label{app:pseudocode}

\begin{algorithm}[h]
\caption{SkillAudit for one fixed candidate}
\label{alg:skillaudit}
\begin{algorithmic}[1]
\REQUIRE Paper $P$, registry $(A,G)$, candidate $A_S$, task $t$, boundary $\Omega$
\STATE Verify source identity, locators, DAG validity, and closure of $A_S$
\STATE Render and freeze $B$, $F=R(A)$, $S=R(A_S)$, and policy $\gamma$
\FOR{each registered block and condition $C\in\{B,F,S\}$}
    \STATE Execute a fresh session and retain its terminal evidence
    \STATE Validate evidence and record the hard-contract outcome
\ENDFOR
\STATE Compute matched outcomes and apply Equation~\ref{eq:decision}
\STATE Emit the evidence record and field-level rationale
\end{algorithmic}
\end{algorithm}

\section{Offline Component Replay}
\label{app:component-ablation}

The component analysis replays the completed Sol ledger and deterministic fixtures without new model calls. On the natural tasks, an $F/S$-only rule yields \AblationFSAccept{} Accept, \AblationFSReject{} Reject-candidate, \AblationFSInconclusiveFull{} full-inconclusive, and \AblationFSInconclusiveEvidence{} evidence-inconclusive states. Adding $B$ changes \AblationBChangedTasks{}/\PrimaryTasks{} task states and yields the distribution in Table~\ref{tab:sol-diagnostic-states}. Because these tasks have no known admission truth and the policy is retrospective, the comparison measures decision sensitivity rather than accuracy.

The deterministic fixtures isolate the integrity logic. A binary contract gate and a digest-only gate each recover \AblationBinaryContractCorrect{}/\AblationTotalFixtures{} exact states. A contract tri-state gate, which distinguishes pass, fail, and missing evidence, recovers \AblationTriStateCorrect{}/\AblationTotalFixtures{}; the full deterministic gate also recovers \AblationFullGateCorrect{}/\AblationTotalFixtures{}. The fixtures therefore show that tri-state contract semantics are necessary for exact state recovery in this suite. Because the tri-state gate already matches every label, these fixtures do not isolate an incremental benefit from the additional digest check or estimate population error rates.

\section{Reproducibility Details}
\label{app:reproducibility}

Primary requests use GPT-5.6 Sol with temperature 0, top-$p$ 1.0, an 8,192-token output ceiling, fresh workspaces, and the registered balanced schedules. The API exposes no enforceable sampling seed. Deterministic case-generation, registry-assignment, schedule, and analysis seeds are retained, and the paper-level bootstrap uses 10,000 fixed-seed resamples. The three reported Sol repetitions are therefore independent calls under the same recorded configuration.

Execution orchestration and analysis were run on Windows 11 (build 26200) with an AMD Ryzen 9 7945HX CPU, 32 logical processors, and 31.7 GB RAM; model inference was remote and used no local GPU. The analysis environment used Python 3.12.7 and Matplotlib 3.9.2. The supplementary artifact includes the canonical ledgers, generated summaries, analysis scripts, source manifests, and SHA-256 checks needed to reproduce the tables and figures from retained terminal rows. Private API credentials are not included.

\section{Terminal-Ledger Scope}
\label{app:terminal-ledger}

All 2,688 retained canonical rows across the full-grid, Controls-v2, and focused suites have complete response bodies, registry bindings, and frozen scorer outcomes; primary claims use only the 1,296 $B/F/S$ rows. The release defines its analysis boundary at this terminal ledger. Earlier nonterminal attempts are outside the retained artifact, so it supports exact reconstruction of the reported summaries but not attempt-level or intention-to-treat analyses beyond the retained rows. Completed hard-contract failures remain in the ledger as valid experimental outcomes.
